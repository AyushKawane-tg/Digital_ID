# Digital Employee ID Card (QR) — POC

A simple MERN proof of concept: an admin creates an employee, a unique QR code is generated, and scanning that QR opens a public digital employee ID card.

```text
Admin Dashboard → Add Employee → MongoDB → Generate QR → Scan → Digital ID Card
```

## Tech stack

| Layer | Tools |
| --- | --- |
| Frontend | React, Vite, Tailwind CSS, Axios |
| Backend | Node.js, Express.js |
| Database | MongoDB, Mongoose |
| QR | `qrcode` npm package |

No authentication, Redis, or cloud storage in this version.

## Prerequisites

- Node.js 18+ (this project was built with Node 24)
- npm
- MongoDB Community Server **or** Docker

## 1. Start MongoDB

### Option A — MongoDB installed locally (Windows)

1. Install [MongoDB Community Server](https://www.mongodb.com/try/download/community).
2. Start the service from Services (`MongoDB`) or run:

```powershell
net start MongoDB
```

If `mongod` is on your PATH:

```powershell
mongod --dbpath "C:\data\db"
```

Create `C:\data\db` first if it does not exist.

### Option B — Docker

```powershell
docker run -d --name employee-mongo -p 27017:27017 mongo:7
```

Default connection string used by this POC:

```text
mongodb://127.0.0.1:27017/employee-id
```

## 2. Backend setup

```powershell
cd backend
copy .env.example .env
npm install
```

`backend/.env`:

```env
PORT=5000
MONGO_URI=mongodb://127.0.0.1:27017/employee-id
FRONTEND_URL=http://localhost:5173
```

`FRONTEND_URL` is used when generating QR codes. Do not hardcode the frontend URL in application code.

Start the API:

```powershell
npm run dev
```

Health check: [http://localhost:5000/api/health](http://localhost:5000/api/health)

## 3. Frontend setup

In a second terminal:

```powershell
cd frontend
npm install
npm run dev
```

Admin dashboard: [http://localhost:5173/admin](http://localhost:5173/admin)

Vite proxies `/api` to `http://localhost:5000`, so the React app can call the backend without extra CORS setup.

## 4. Seed sample employees

With MongoDB running:

```powershell
cd backend
npm run seed
```

This replaces existing employees with 5 sample records (`EMP1001`–`EMP1005`) across Engineering, HR, Design, Finance, and Infrastructure. One employee is `INACTIVE`.

Refresh `/admin` after seeding.

## 5. How to run the POC

1. Start MongoDB.
2. Seed data (optional but recommended).
3. Start backend: `cd backend; npm run dev`
4. Start frontend: `cd frontend; npm run dev`
5. Open [http://localhost:5173/admin](http://localhost:5173/admin)
6. Click **+ Add Employee**, submit the form, and note the generated ID (for example `EMP1006`).
7. Click **Generate QR** on a row.
8. Scan the QR (or click **Open ID**) to view `/id/EMP1001`.

## Postman API examples

Base URL: `http://localhost:5000`

### Create employee

`POST /api/employees`

```json
{
  "name": "Ayush Kawane",
  "email": "ayush@company.com",
  "phone": "+91-9876543210",
  "company": "Teleglobals International",
  "designation": "Software Engineer",
  "department": "Engineering",
  "reportingHead": "Rahul Sharma",
  "officeAddress": "CEREBRUM IT PARK, B-3, Kalyani Nagar, Pune, Maharashtra 411014",
  "photo": "",
  "status": "ACTIVE"
}
```

Employee ID is generated by the server (`EMP1001`, `EMP1002`, …).

### List employees

`GET /api/employees`

### Get one employee

`GET /api/employees/EMP1001`

### Update employee

`PUT /api/employees/EMP1001`

```json
{
  "designation": "Senior Software Engineer",
  "status": "ACTIVE"
}
```

### Delete employee

`DELETE /api/employees/EMP1001`

### Generate QR

`GET /api/employees/EMP1001/qr`

Response includes:

- `name`
- `employeeId`
- `digitalIdUrl` (example: `http://localhost:5173/id/EMP1001`)
- `qrCode` — PNG data URL the React app can display in an `<img src="...">`

### Public digital ID

`GET /api/id/EMP1001`

Returns only ID-card fields. MongoDB internals (`_id`, `__v`) are not exposed.

## How to test QR scanning on a phone

A phone cannot open `localhost` on your computer. Use your PC’s LAN IP.

1. Put the phone and the computer on the same Wi-Fi network.
2. Find your IPv4 address:

```powershell
ipconfig
```

Look for something like `192.168.1.24`.

3. Update `backend/.env`:

```env
FRONTEND_URL=http://192.168.1.24:5173
```

4. Restart the backend, then click **Generate QR** again.
5. Scan the QR with the phone camera.
6. The phone should open `http://192.168.1.24:5173/id/EMP1001` and show the digital ID card.

The Vite dev server already listens on all interfaces (`host: true`) so phones on the LAN can reach it.

If Windows Firewall blocks port `5173`, allow Node.js / Vite through the firewall for private networks.

## Error handling

The API returns user-friendly messages for:

- Employee not found (`404`)
- Duplicate employee ID (`409`)
- Invalid employee data (`400`)
- MongoDB connection failure (process exits on startup)
- QR generation failure (`500`)

The frontend shows those messages on the dashboard, add-employee form, and public ID page.
